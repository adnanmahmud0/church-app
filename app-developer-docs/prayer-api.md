# Prayer API Documentation (Mobile App)

This document outlines the REST API endpoints available for the Church App's native Prayer module. 

## Base URL
All endpoints are relative to the main API base URL:
`https://<server-domain>/api/v1/prayer`

---

## Authentication Note
The Prayer module utilizes an **Optional Authentication** approach for certain endpoints to allow guests (unauthenticated users) to interact with the system using a `device_fingerprint`.

- When a user **is** logged into the app, send their standard Bearer token in the header:
  `Authorization: Bearer <your_jwt_token>`
- When a user is **not** logged in, omit the header, but ensure a unique string is passed to `device_fingerprint` in the request body where required.

---

## 1. Create a Prayer Request
Allows a user (authenticated or guest) to submit a new prayer request.

**Request**
`POST /requests`

**Body Parameters (JSON)**
- `content` (required, string): The prayer request text (10 - 500 characters).
- `author_name` (optional, string): Name of the person requesting prayer. Defaults to "Anonymous". Max 50 chars.
- `is_anonymous` (optional, boolean): Whether to hide the author's name from public view. Defaults to true.

**Example Request**
```json
{
  "content": "Please pray for my mother's upcoming surgery.",
  "author_name": "John Doe",
  "is_anonymous": false
}
```

**Example Response (201 Created)**
```json
{
  "success": true,
  "statusCode": 201,
  "message": "Prayer request created successfully",
  "data": {
    "_id": "60d5ec49c4f...",
    "content": "Please pray for my mother's upcoming surgery.",
    "author_name": "John Doe",
    "is_anonymous": false,
    "status": "active",
    "pray_count": 0,
    "author_user_id": "60d5e23...", 
    "createdAt": "2026-06-05T00:00:00Z"
  }
}
```

## 2. Get All Active Prayer Requests
Fetches a paginated list of active prayer requests. **No authentication required.**

**Request**
`GET /requests?page=1&limit=10`

**Query Parameters**
- `page` (optional, number): Default is 1.
- `limit` (optional, number): Default is 10.

**Example Response (200 OK)**
```json
{
  "success": true,
  "statusCode": 200,
  "message": "Prayer requests retrieved successfully",
  "pagination": {
    "page": 1,
    "limit": 10,
    "totalPage": 5,
    "total": 48
  },
  "data": [
    {
      "_id": "60d5ec49c4f...",
      "content": "Please pray for my mother's upcoming surgery.",
      "author_name": "John Doe",
      "is_anonymous": false,
      "status": "active",
      "pray_count": 5,
      "createdAt": "2026-06-05T00:00:00Z"
    }
  ]
}
```

## 3. Get My Prayer Requests
Fetches all prayer requests authored by the currently logged-in user. **Requires Authentication.**

**Request**
`GET /requests/mine`

**Headers**
- `Authorization`: `Bearer <token>`

**Example Response (200 OK)**
```json
{
  "success": true,
  "statusCode": 200,
  "message": "Your prayer requests retrieved successfully",
  "data": [ ... ]
}
```

---

## 4. Get a Single Prayer Request
Fetches the details of a specific prayer request by ID.

**Request**
`GET /requests/:id`

**Example Response (200 OK)**
```json
{
  "success": true,
  "statusCode": 200,
  "message": "Prayer request retrieved successfully",
  "data": {
    "_id": "60d5ec49c4f...",
    "content": "Please pray for...",
    ...
  }
}
```

---

## 5. Pray for a Request
Increments the `pray_count` of a specific prayer request. This endpoint prevents double-counting by logging the interaction against the user's ID or device fingerprint.

**Request**
`POST /requests/:id/pray`

**Body Parameters (JSON)**
- `device_fingerprint` (required if NOT logged in, string): A unique device identifier generated by the mobile app.

**Example Request (Guest User)**
```json
{
  "device_fingerprint": "a1b2c3d4-uuid-from-app"
}
```

**Example Response (200 OK)**
```json
{
  "success": true,
  "statusCode": 200,
  "message": "Successfully prayed for this request",
  "data": {
    "_id": "60d5ec49c4f...",
    "pray_count": 6
    ...
  }
}
```

---

## 6. Update a Prayer Request
Allows the author to update the status or content of their own prayer request. **Requires Authentication.**

**Request**
`PATCH /requests/:id`

**Body Parameters (JSON)**
- `content` (optional, string): Updated text.
- `status` (optional, string): Must be one of `"active"`, `"answered"`, or `"archived"`.

**Example Request**
```json
{
  "status": "answered"
}
```

---

## 7. Delete (Archive) a Prayer Request
Allows the author (or an Admin) to soft-delete a prayer request. This changes the status to `"archived"` so it no longer appears in the public feed. **Requires Authentication.**

**Request**
`DELETE /requests/:id`

**Example Response (200 OK)**
```json
{
  "success": true,
  "statusCode": 200,
  "message": "Prayer request deleted successfully",
  "data": { ... }
}
```
